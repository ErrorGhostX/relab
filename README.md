# Relab

Мобильное приложение для управления заказами на ремонт и диагностику электронных устройств с поддержкой офлайн-работы и синхронизации данных.

## 📱 Описание

Relab — это полнофункциональное Android-приложение для мастеров по ремонту устройств, которое позволяет:

- 📝 Создавать и управлять заказами на ремонт и диагностику
- 📸 Добавлять фотографии устройств
- 💼 Отслеживать услуги и формировать отчеты
- 📊 Просматривать аналитику (доходы, статистика выполненных заказов)
- 🏢 Работать с несколькими сервисными центрами (Мульти-компании)
- 📴 Работать полностью автономно в режиме "Локальный гость"
- 📦 Вести учет расходных материалов и запчастей (Склад)
- 🤖 Использовать ИИ для парсинга текста заказа
- 👥 Управлять персоналом (создание и редактирование сотрудников)
- 💬 Корпоративный мессенджер с личными и групповыми чатами
- 🔔 Push-уведомления через Firebase Cloud Messaging
- 🌐 Работать офлайн с последующей двухсторонней синхронизацией
- 📄 Генерировать PDF-отчеты по заказам
- 👤 Управлять профилем пользователя (свой и чужие — для admin/manager)
- 📡 Сетевые инструменты для выездных техников (Speed Test, Ping, WiFi-анализатор)
- 🛠️ Набор полезных инструментов (ADB, драйверы, ИК-пульт)

### Установка Backend

1. Перейдите в директорию backend:
```bash
cd backend_relab_app
```

2. Создайте виртуальное окружение:
```bash
python -m venv venv
source venv/bin/activate  # На Windows: venv\Scripts\activate
```

3. Установите зависимости:
```bash
pip install -r requirements.txt
```

4. Выполните миграции:
```bash
python manage.py migrate
```

5. Создайте суперпользователя (опционально):
```bash
python manage.py createsuperuser
```

6. Запустите сервер разработки:
```bash
python manage.py runserver 0.0.0.0:8000
```

> **Примечание**: Для WebSocket/чатов используйте `daphne -b 0.0.0.0 -p 8000 backend_relab_app.asgi:application`. На Windows при проблемах с Daphne используйте `python manage.py runserver --noasgi` для стабильной REST-разработки.

Сервер будет доступен по адресу: `http://localhost:8000`

### Настройка Android приложения

1. Откройте проект в Android Studio
2. Запустите приложение на эмуляторе или устройстве.
3. На экране входа нажмите на **Шестеренку** (Настройки).
4. Введите IP-адрес или домен вашего сервера (например, `http://192.168.1.50:8000`). Приложение автоматически подтянет название компании и сохранит конфигурацию.
5. Выберите компанию из выпадающего списка и выполните вход.

*Для тестирования без сервера вы можете использовать кнопку **"Локальный гость"** — это создаст изолированную локальную БД без необходимости настройки сети.*

## 🔑 Основные функции

### Управление заказами
- Создание новых заказов с подробной информацией
- Редактирование существующих заказов
- Просмотр списка всех заказов с первой фотографией
- Переключатель вида: **Сетка (Grid)** или **Список (List)**
- Фильтрация по статусу (Новый, В процессе, Готов, Ожидаемый)
- Загрузка нескольких фотографий устройств с горизонтальным скроллом
- Копирование номера заказа и мессенджера в буфер обмена
- Поддержка "челки" (Display Cutout) для полноэкранного интерфейса деталей заказа
- Указание адреса клиента и типа выезда (в мастерской / выездной)

### Умный ИИ-Парсинг
- Интеграция с Ollama/OpenAI.
- Автоматическое распределение неструктурированного текста (из мессенджера) по полям: Клиент, Телефон, Устройство, Проблема.

### Склад и Расходники
- Учет наличия запчастей.
- Списание остатков при добавлении детали к заказу.
- Автоматический подсчет стоимости запчастей в итоговой сумме.

### Управление сотрудниками
- Регистрация новых сотрудников (admin/manager) с указанием email, телефона, ФИО, ранга.
- **Редактирование профилей** сотрудников (admin/manager может менять ФИО, телефон, email, ранг, специализацию, активность).
- Просмотр списка сотрудников с аватарами и ролями.
- **Редактирование чужого профиля** при открытии карточки сотрудника (кнопка "Сохранить" в шапке).
- Long-press для быстрого редактирования из списка.

### Мульти-компании и Локальный Гость
- Поддержка переключения между разными бэкендами прямо с экрана входа.
- Встроенная автоматическая проверка валидности сервера.
- Полностью изолированный режим "Локальный Гость" (используется отдельный файл базы данных `relab_guest.db`), в котором синхронизация отключена.
- Динамическое переключение Room-базы: `relab_guest.db`, `relab_default.db` или хеш-компании.

### Корпоративный мессенджер
- Личные (direct) и групповые чаты.
- Интеграция с заказами (обсуждение заказа в привязанном чате).
- Отправка сообщений и голосовых заметок.
- Push-уведомления о новых сообщениях через Firebase Cloud Messaging.

### Услуги и отчеты
- Добавление услуг к заказам с указанием цены
- Удаление услуг
- Автоматический расчет итоговой стоимости
- Генерация PDF-отчетов с логотипом компании

### Аналитика
- Месячный доход (сумма выполненных заказов) с красивым оформлением
- Количество завершенных заказов за месяц
- Графики: кумулятивные доходы, статистика по статусам (pie chart, 30 дней)
- Аналитика доступна для Admin и Manager ролей
- Просмотр аналитики по конкретному сотруднику

### Профиль пользователя
- Управление персональными данными
- Загрузка аватара
- Указание ФИО, email, номер телефона
- Отображение ранга (Администратор, Руководитель, Сотрудник, Стажёр)
- Недавние заказы в профиле
- **Admin/Manager**: возможность редактировать и сохранять изменения в чужих профилях

### 📡 Сетевые инструменты (для выездных техников)
- **WiFi-анализатор**: SSID, IP-адрес, уровень сигнала (dBm), шлюз, скорость канала
- **Speed Test**: встроенный тест скорости скачивания (10MB файл с CDN, результат в Mbps)
- **Ping**: ввод IP/домена → живой терминал с пошаговым выводом результатов (5 пакетов)
- Автозапрос разрешения на Локацию для полного WiFi-инфо, fallback через ConnectivityManager

### Другие инструменты
- ИК-пульт (интерактивное руководство + ссылка на Play Market)
- Скачивание и установка драйверов Relab
- ADB инструменты (скачивание, руководство, настройки разработчика)

### Офлайн-режим
- Полная работа без интернета
- Локальное хранение в Room Database
- Ручная синхронизация кнопкой (с индикацией статуса)
- Автоматическая периодическая синхронизация (настраиваемый интервал)
- Разрешение конфликтов при синхронизации (приоритет у локальных данных)
- Кнопка очистки локальной БД на экране заказов

## 🔐 Аутентификация

Приложение использует JWT (JSON Web Tokens) для аутентификации:

- **Access Token**: действителен 1 день
- **Refresh Token**: действителен 7 дней
- Автоматическое обновление токенов
- Сохранение токенов в локальном хранилище

## 📡 API Endpoints

### Аутентификация (Djoser)
- `POST /auth/users/` - Регистрация пользователя (Создание сотрудника, с email)
- `POST /auth/token/login/` - Получение JWT токена
- `POST /auth/token/refresh/` - Обновление токена
- `GET /auth/users/me/` - Информация о текущем пользователе
- `PATCH /auth/users/me/` - Обновление профиля

### Компании
- `GET /api/company/info/` - Получение названия и логотипа компании по IP

### Заказы
- `GET /api/orders/` - Список всех заказов (фильтрация по автору, публичности, назначению)
- `POST /api/orders/` - Создание заказа (JSON)
- `POST /api/orders/create-with-photo/` - Создание заказа с фотографией (multipart/form-data)
- `GET /api/orders/{id}/` - Детали заказа
- `PUT /api/orders/{id}/` - Обновление заказа
- `DELETE /api/orders/{id}/` - Удаление заказа
- `POST /api/orders/{id}/add_service/` - Добавление услуги
- `DELETE /api/orders/{id}/services/{service_id}/` - Удаление услуги
- `GET /api/orders/{id}/report/` - Получение PDF-отчета

### Сотрудники
- `GET /api/employees/` - Список всех сотрудников
- `PATCH /api/employees/{id}/update_profile/` - Редактирование профиля сотрудника (admin/manager)

### Клиенты
- `GET, POST, PUT, DELETE /api/customers/` - Управление базой клиентов

### Склад
- `GET, POST, PUT, DELETE /api/consumables/` - Управление складом и расходниками
- `GET, POST, DELETE /api/order-consumables/` - Привязка расходников к заказам

### Чаты
- `GET, POST /api/chats/` - Список и создание чат-комнат
- `GET /api/chats/{id}/messages/` - История сообщений
- `POST /api/chats/{id}/send_message/` - Отправка сообщения

### Push-уведомления
- `POST /api/devices/` - Регистрация FCM-токена устройства

### Аналитика
- `GET /api/analytics/monthly_earnings/` - Месячный доход
- `GET /api/analytics/monthly_completed_orders/` - Количество завершенных заказов
- `GET /api/admin-analytics/` - Административная аналитика по сотрудникам

## 💾 База данных

### Backend (Django Models)
- **Order**: Заказы (номер, клиент, устройство, статус, тип, адрес, тип выезда и т.д.)
- **Service**: Услуги, привязанные к заказам
- **UserProfile**: Расширенный профиль (ФИО, аватар, телефон, ранг, специализация)
- **Customer**: База клиентов (ФИО, телефон, email, мессенджер, адрес)
- **Consumable**: Расходные материалы (название, артикул, количество, цена)
- **OrderConsumable**: Привязка расходников к заказам
- **ChatRoom / Message**: Чат-комнаты и сообщения
- **FCMDevice**: Устройства для Push-уведомлений

### Android (Room Database)
- **OrderEntity**: Локальное представление заказов (с `syncStatus`)
- **ServiceEntity**: Локальное представление услуг
- **CustomerEntity**: Локальные клиенты
- **ConsumableEntity**: Локальные расходники
- **ChatRoomEntity / StaffEntity**: Кеширование чатов и сотрудников

## 🔄 Синхронизация

Приложение реализует двухстороннюю синхронизацию:

1. **Pull**: Получение обновлений с сервера (только если локальные данные не изменены)
2. **Push**: Отправка локальных изменений на сервер (включая фотографии, клиентов, расходники)
3. **Conflict Resolution**: Разрешение конфликтов (приоритет у локальных данных)

Синхронизация происходит:
- **По запросу пользователя** (кнопка синхронизации на экране заказов)
- **Автоматически** (настраиваемый интервал в Настройках, минимум 1 минута)
- Только при наличии подключения к серверу (проверка через индикатор)
- Пропускается в режиме "Локальный Гость"
